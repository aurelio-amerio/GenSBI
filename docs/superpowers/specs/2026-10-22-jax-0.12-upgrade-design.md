# JAX 0.12 compatibility upgrade — design

Date: 2026-10-22. Branch: `jax-0.12` (worktree `../GenSBI-jax-0.12`, off `main` @ 8653d33).

## Intent

JAX 0.12 is out. GenSBI currently declares `jax>=0.10.2,<0.12.0` and is locked at 0.11.0.
Past minor bumps (0.10 → 0.11) broke functions, and some deps (diffrax, numpyro, flax,
orbax) lag new JAX minors. We want to find out, in a controlled way, whether GenSBI and its
dependency stack work on 0.12, fix what breaks or is deprecated in our own code, refresh the
dependency floors, and publish the result as **GenSBI 0.5.0**.

This is routine hygiene, not a response to a reported breakage. The policy going forward is
that the latest GenSBI release supports the current and the previous JAX minor (here: 0.11.x
and 0.12.x), so users are never forced onto the newest JAX. JAX 0.10 support is dropped.

## Goals

1. Establish, with test evidence, that GenSBI works on JAX 0.12 with a freshly resolved
   dependency stack.
2. Fix deprecation warnings and breakages that originate in GenSBI's own source, including
   those caused by the other deps moving (blackjax, numpyro, flax, orbax, ...), not only by
   JAX itself.
3. Raise the floors of all dependencies to the freshly resolved versions, and set the JAX
   range to `>=0.11.<lowest passing patch>,<0.13`.
4. Verify the lower end of that range (JAX 0.11.x) actually passes with the new floors.
5. Confirm sbibm-jax and heal-swin-nnx (GenSBI's own sibling deps, both with no JAX ceiling)
   also run on 0.12, and patch them only if they actually break or deprecate.
6. Ship as GenSBI 0.5.0 (minor: JAX floor raised, all dep floors raised).

## Non-goals

- Adopting new JAX 0.12 features or refactoring beyond what the upgrade requires.
- Working around deprecation warnings that originate inside third-party deps.
- Keeping JAX 0.10.x working. It is dropped on purpose.
- GPU validation. CPU tiers and docs are the gate here; the GPU sanity run is the owner's
  step after the branch is ready, as usual.
- Changing the `extraslow` tier's exclusion from CI.

## Anti-goals (what would make this a failure even if it "works")

- Touching `main`'s working tree, `.venv`, `uv.lock` or the `gensbi` mamba env. All work
  happens in the worktree with its own fresh venv.
- Shipping a range we have not actually tested at both ends.
- Shipping with `[tool.uv] override-dependencies` or any other trick that hides a dep's own
  JAX ceiling. If a dep declares `jax<0.12`, users cannot install the combination, so GenSBI
  cannot claim 0.12 support until that dep releases. Overrides may be used for *diagnosis*
  only (to learn whether the dep's ceiling is real or conservative) and never committed.
- Papering over a dep that resolves on 0.12 but breaks at runtime inside its own code (the
  most likely way 0.12 actually fails, since no direct dep declares a ceiling and diffrax has
  lagged before). That is treated like a ceiling: stop, report, do not claim 0.12 support.
  A GenSBI-side workaround is considered only if the owner approves it after seeing the
  report.
- Silently narrowing the suite (skipping tiers, deselecting failing tests) to get green.

## Constraints

- Python 3.12, as in CI. All test runs use `JAX_PLATFORMS=cpu` (already set via pytest-env).
- CI tiers are the definition of "green": `not slow and not experimental and not extraslow`,
  then `slow`, then `experimental`, plus the Sphinx docs build (`uv sync --group docs`,
  `make html` in `docs/`). Lint (`flake8 --select=E9,F63,F7,F82`) must also pass.
- sbibm-jax and heal-swin-nnx are installed from their sibling checkouts
  (`../sbibm-jax` @ 6ffe721, `../HEAL-SWIN-nnx` @ de33b81), editable, so their tests can be
  run against the same resolved stack. Their torch / HF / jaxhp / pypesto extras are out of
  scope; only the JAX-dependent portions of their suites matter.
- The "strict" probe means `jax==0.12.<latest patch>` pinned exactly, letting uv resolve
  everything else fresh. The same applies to the 0.11.x probes.

## Versioning and floor rule (decided by the owner)

- GenSBI ships as **0.5.0** regardless of what breaks: the JAX floor moves to 0.11 and all
  dependency floors are raised, which is a minor bump by the project's convention.
- **Dependency floors** become the versions the fresh 0.12 resolve picks (the same
  convention the current pyproject follows, where floors mirror lock versions), with one
  constraint: every floor must still resolve on the chosen JAX 0.11.x floor. If the newest
  version of some dep requires `jax>=0.12`, that dep's floor is set to the newest version
  that still allows JAX 0.11.x instead, and this is noted in the report.
- **JAX range**: `>=0.11.<p>,<0.13`, where `p` is the lowest 0.11 patch that (a) resolves
  with the new dep floors and (b) passes the full CPU gate. Known input: flax 0.12.9+ already
  requires jax>=0.11.1, so `p` is likely 1 or 2, not 0. 0.11.0 is what `main` is locked at
  today, so if it is excluded the report says so explicitly.
- If no 0.11.x passes, that violates the "current + previous minor" policy. Do not ship a
  `>=0.12` floor unilaterally: report what breaks on 0.11 and whether a small version-guarded
  shim in GenSBI would fix it, and let the owner decide.
- The same JAX range must be applied in all four places in `pyproject.toml`:
  `dependencies`, `cuda12`, `cuda13`, `tpu`.
- Breakage caused by a non-JAX dep moving (e.g. blackjax 1.6 → 1.7, numpyro 0.21 → 0.22) is
  in scope and is fixed forward against the new API. No compat path for the old dep version
  is required, since the floor is being raised anyway.

## Deprecation policy

- Run the tiers with deprecation warnings surfaced (e.g. `-W always::DeprecationWarning`,
  `-ra`) and classify each warning by where its stack points.
- Warnings pointing into `src/gensbi` (or into sbibm-jax / heal-swin-nnx source) are fixed
  in that repo, using the replacement JAX (or the dep) recommends. A fix must keep the
  JAX 0.11 floor working: prefer replacements available since the floor; if none exists, a
  small version-guarded shim is acceptable.
- Warnings pointing into third-party deps are listed in the final report with the dep and
  message, and otherwise ignored.
- Pre-existing warnings unrelated to the upgraded stack (e.g. from sklearn or matplotlib)
  are out of scope; note them if cheap, do not chase them.

## CI floor job (builder's call, owner may veto)

After widening to `<0.13`, CI's plain `uv sync` will always resolve to 0.12.x, so the
"current + previous minor" promise would be verified exactly once, by hand, on this branch.
Add a second test job to `python-app.yml` that installs with `jax==<the chosen 0.11 floor>`
and runs only the fast tier (`not slow and not experimental and not extraslow`). It does not
feed the junit/badge merge; it is a pass/fail smoke check. Cost is one fast-tier run per push.

## Plan of work (in order)

1. **Isolation.** Worktree `../GenSBI-jax-0.12` on branch `jax-0.12` (done). Create a fresh
   uv venv inside it. Nothing in this branch's env or lock is shared with `main`.
2. **Strict 0.12 probe.** Pin `jax==0.12.x` in the worktree's `pyproject.toml`, `uv sync`
   with the `test` and `docs` groups, install the two sibling repos editable. Record whether
   resolution succeeds and which deps moved (flax, orbax, diffrax, equinox, numpyro, optax,
   blackjax, grain, safetensors: versions before/after).
   - Resolution failure caused by a dep's JAX ceiling → stop, report the blocking dep and its
     tracker/release status. Optionally diagnose with a non-committed override.
3. **Gate at 0.12.** Lint, three test tiers, docs build; then sbibm-jax and heal-swin-nnx
   test suites against the same env. Collect failures and deprecation warnings. A failure
   inside a dep's own code → stop and report (see anti-goals).
4. **Fix.** Address failures and in-repo deprecations (GenSBI first; siblings only where
   affected), whether caused by JAX or by another dep moving. Each fix is a focused commit.
   Re-run the affected tier(s) until green.
5. **Floor probe.** With the candidate dep floors, repeat resolve + full gate at the latest
   0.11.x. If it passes, probe the lowest 0.11 patch that resolves with the new floors
   (bisecting at most the one or two patches in between). Apply the floor rule.
6. **Finalize.** Set the four JAX ranges and all dep floors, bump `version` to 0.5.0,
   regenerate the worktree's `uv.lock` (gitignored, but keep it consistent for local use),
   update any README/docs text that states supported JAX versions, add the CI floor job.
   For the siblings: pyproject touch and patch version bump only if their code changed; if
   heal-swin-nnx or sbibm-jax needs a release, GenSBI's floor for it moves too and the report
   flags the release ordering (sibling first).
7. **Report.** A short compatibility matrix (jax version × tier × result), the before/after
   dep floor table, and the list of dep-internal deprecations, in the branch's PR description
   and in the final summary to the owner. Hand-off: PR-ready branch; GPU sanity run, merge
   and release are the owner's.

## Left to the builder

  re-synced or one venv per probe.
- How to run the sibling suites (from inside the GenSBI venv vs. their own worktrees), as
  long as they run against the same resolved JAX.
- Mechanism for collecting and classifying warnings.
- Whether to diagnose a blocking dep ceiling with an override, and how to phrase the
  blocker report.
- Order and granularity of fix commits.
- Which sbibm-jax tests count as "JAX-dependent" when its optional extras are absent.

## Notes for the builder

- `uv.lock` is gitignored in this repo; version ranges in `pyproject.toml` are the source of
  truth for users. Do not try to commit the lock.
- Historically, `.venv` on `main` sometimes hid test failures that the mamba `gensbi` env
  surfaced (cause unknown). A fresh venv per probe avoids stale state; if results look
  suspiciously clean compared to history, re-check the env is what you think it is
  (`uv run python -c "import jax; print(jax.__version__, jax.__file__)"`).
- The mamba `gensbi` env imports `../sbibm-jax` editable; do not modify that checkout's
  working tree in place for experiments. Use a worktree or branch for any sibling fixes.
- The `extraslow` tier is excluded from CI and from this gate.
