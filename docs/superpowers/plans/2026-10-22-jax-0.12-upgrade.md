# JAX 0.12 Compatibility Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove GenSBI, sbibm-jax and heal-swin-nnx run on JAX 0.12.0.1 and 0.11.x with a freshly resolved dependency stack, fix what breaks in our own code, and ship GenSBI 0.5.0 declaring `jax>=0.11.<p>,<0.13` with all dependency floors raised.

**Architecture:** This is a probe-and-fix maintenance plan, not a feature build. Each probe is a fresh uv environment inside the worktree (selected with `UV_PROJECT_ENVIRONMENT`), the gate is the exact CI command set plus the two sibling suites, and every probe result lands in a committed compatibility report. Fix tasks are conditional on probe output; the plan fixes their rules and stop conditions, not their content.

**Tech Stack:** uv 0.11.7, Python 3.12, pytest (+xdist, +env), flake8, Sphinx; JAX 0.12.0.1 / 0.11.2 / 0.11.1.

**Spec:** `docs/superpowers/specs/2026-10-22-jax-0.12-upgrade-design.md`

- Every probe env is created with `UV_PROJECT_ENVIRONMENT=$WT/.venv-<name>`; never reuse one env for two JAX versions.

- Gate = lint (`flake8 --select=E9,F63,F7,F82`), tiers `not slow and not experimental and not extraslow`, `slow`, `experimental`, docs `make html`, plus `$SB/tests` and `$HS/tests`. All CPU (`JAX_PLATFORMS=cpu` comes from pytest-env). `extraslow` is never run.
- Dep-internal runtime failure (traceback bottoms out inside a third-party package, not in `src/gensbi`, `sbibm_jax` or `heal_swin_nnx`) = stop, report, do not claim 0.12 support. No `override-dependencies` in any commit.
- Deprecations attributed to `gensbi`, `sbibm_jax` or `heal_swin_nnx` modules are fixed; those attributed to third-party modules are listed in the report only.
- Final versions: GenSBI `0.5.0`; JAX range identical in `dependencies`, `cuda12`, `cuda13`, `tpu`; dep floors = versions resolved in Task 1 (except a dep whose newest release needs `jax>=0.12`, which is floored at the newest release allowing 0.11).
- Report file: `docs/superpowers/2026-10-22-jax-0.12-compat-report.md`, updated and committed at the end of every task.
- Pytest parallelism: pass `-n 8` on this 64-core node (overrides the `-n 2` in `addopts`).

## Review Focus

1. **The three accelerator extras drift from `dependencies`.** A user installing `gensbi[cuda12]` must get the same JAX range as a CPU user. Pinned by Task 6 step 3 (exact-count grep).
2. **The CI floor job quietly tests 0.12.** If `uv pip install jax==0.11.p` fails or a later step re-syncs, the job passes on the wrong JAX. Pinned by the version assertion step inside the job (Task 6 step 6).
3. **The in-repo deprecation filter misses warnings** because JAX attributes some with a `stacklevel` that lands in its own modules. Pinned by Task 2 step 4 (grep of the warnings summary for `src/gensbi/` paths in addition to the `-W error` filter).
4. **`uv sync` evicts the editable siblings**, so sibling tests silently import the PyPI `sbibm-jax 0.1.4` / `heal-swin-nnx 0.1.1` instead of the checkouts. Pinned by Task 1 step 5 and Task 3 step 1 (`__file__` assertions).
5. **jaxlib left at 0.12 in a 0.11 probe.** `jax==0.12.0.1` accepts `jaxlib>=0.11.2`, so a half-downgrade imports but is not the stack users get. Pinned by Task 5 step 2 (assert both `jax.__version__` and `jaxlib.__version__`).
