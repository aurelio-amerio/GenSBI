gensbi.sharding#

Multi-device sharding helpers for GenSBI.

Models annotate their variables with logical axis names through axes() (or partitioned() for explicit initialisers). Annotations are inert: nothing is placed on a device until shard_model() maps the logical names onto the axes of a jax.sharding.Mesh according to a named rule ("replicated", "fsdp" or "tensor"). With no mesh, nothing changes.

Cross-repo contract#

LOGICAL_AXES, RULES, MODEL_AXIS and the semantics of axes, partitioned, make_mesh, batch_axes, batch_size_divisor, shard_model, shard_batch, check_batch_divisible and sharding_of are identical to heal_swin_nnx/sharding.py. Neither package imports the other; a test pins the vocabulary against the installed heal_swin_nnx. Change both files together.

gensbi.sharding.shard_model(node, mesh, rule='replicated')[source]#

Place every variable of node on mesh according to rule.

Works in place and is idempotent. node is any NNX graph node (modules, nnx.Optimizer, EMA containers). Variables without annotation are replicated; variables with an unknown logical name, a dimension not divisible by the mapped mesh axis, or a mapped axis missing from mesh fall back to replicated and are reported in a single warning. "replicated" ignores annotations (so never warns about them); under other rules unannotated nnx.Param s are replicated and listed in that warning too.

Parameters:

  • node (nnx graph node) – Object whose state is placed.

  • mesh (jax.sharding.Mesh) – Target mesh.

  • rule ({"replicated", "fsdp", "tensor"}, optional) – Logical-to-mesh axis rule. Anything but "replicated" is experimental and warns on every call.

Raises:

ValueError – If rule is not a key of RULES.

Return type:

None
